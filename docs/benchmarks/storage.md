# Storage benchmark

- Run: 2026-10-16T22:47:47+00:00; dataset `data/generated`, 20,000 transactions; 2,000 sequential samples per latency test.
- Host: 12 CPUs, Linux-6.14.0-37-generic-x86_64-with-glibc2.39; single-node Docker stores (Cassandra RF=1, MongoDB standalone), client on the same host.
- Generated by `python -m fraudx.bench` (`make bench`). Local numbers: compare the stores with each other, not with production figures.

## MongoDB vs Cassandra (transaction history)

Each store serves the same two queries with its own data model: Cassandra writes two denormalised tables per transaction (`transactions_by_id`, `transactions_by_customer`); MongoDB writes one document plus a secondary index.
Write path per batch: Cassandra gets two prepared INSERTs per transaction, sent concurrently (64 in flight) by the Python driver; MongoDB gets one unordered `bulk_write` request.

| metric | Cassandra | MongoDB |
| --- | --- | --- |
| batch write throughput (events/s, batches of 500) | 3,964 | 27,308 |
| storage on disk after flush/checkpoint (data + indexes) | 2.75 MiB | 2.12 MiB |
