## 4. Cleaning

Rows 5,078,345 → **4,481,694**; positive labels 5,177 → **4,514**.
Actions: `drop_rows` removes rows, `drop_column` removes a column, `transform` changes values, `flag` documents an issue that is kept on purpose.

| # | rule | action | rows | positives | rationale |
| --- | --- | --- | --- | --- | --- |
| 1 | `invalid_values` | drop_rows | 0 | 0 | Unparseable timestamps/amounts/labels or unknown currency/format can't be mapped to the event contract. |
| 2 | `exact_duplicates` | drop_rows | 9 | 0 | Identical rows (same minute, accounts, amounts, format, label) are load artefacts; keep the first. |
| 3 | `fx_to_usd` | transform | 3,183,167 | 3,265 | Amounts in 15 currencies are not comparable; features (customer mean/std, window sums) need one unit. Converted to USD with rates derived from the data itself; the original amount and currency are kept on the event. |
| 4 | `self_transfers` | drop_rows | 591,212 | 11 | Money moved from an account to itself ('Reinvestment' and currency conversions: 96 % of USD conversions are self-transfers) is not a payment between parties, adds self-loops to the graph, and is rejected by the platform's validation (source == destination). FX rates are derived before this rule. |
| 5 | `simulation_tail` | drop_rows | 715 | 652 | After the simulated period ends, the generator keeps emitting only the remaining steps of laundering patterns: days with < 1 % of median volume are mostly laundering. Kept, they would dominate a time-based test set. |
| 6 | `non_positive_amount` | drop_rows | 0 | 0 | A payment of zero or less is not a money movement. |
| 7 | `below_one_cent` | drop_rows | 4,715 | 0 | Amounts under half a cent round to 0.00 USD (mostly tiny Bitcoin transfers) and become zero-value payments in a 2-decimal contract. |
| 8 | `unknown_sender_owner` | flag | 0 | 0 | Sender account missing from the accounts file: the account itself becomes the customer id. |
| 9 | `no_bank_country` | flag | 2,144,893 | 2,125 | Kept with empty location: the sender's bank name doesn't state a country (generic or city names). The country isn't guessed. |
| 10 | `laundering_without_pattern` | flag | 1,968 | 1,968 | Laundering rows not listed in the patterns file keep scenario `laundering_unattributed`. |

## 5. Mapping to the platform contract (`TransactionEvent` v1)

| raw | canonical | transformation |
| --- | --- | --- |
| (raw row number) | transaction_id | `AML-<row>`, traceable to the raw file line |
| Timestamp | event_time | minute resolution, interpreted as UTC |
| From Bank + Account | source_account | `<bank>:<account>`, bank id without leading zeros |
| To Bank + Account | destination_account | same normalisation |
| accounts.Entity ID (of sender) | customer_id | `E-<entity>`: the account owner (one entity can own several accounts) |
| Amount Paid x FX(Payment Currency→USD) | amount, currency=USD | rates derived from the data's own cross-currency transfers (median) |
| Amount Paid, Payment Currency | original_amount, original_currency | exact original value; Bitcoin → `XBT` |
| Payment Format | payment_method | ACH, WIRE, CHEQUE, CREDIT_CARD, CASH, BITCOIN |
| - | transaction_type | TRANSFER (every row moves money between two accounts) |
| accounts.Bank Name (sender) | location.country | only when the bank name states a country (`Germany Bank #…`); else empty |
| Is Laundering | is_fraud_label | laundering is the positive class |
| Patterns file | scenario | pattern type (`fan_out`, `cycle`…), `laundering_unattributed` or `normal` |
| Amount Received, Receiving Currency | - | dropped after FX derivation |

## 8. Limitations

- Synthetic (calibrated simulator), not real bank data.
- Laundering is rare (≈0.1 %) and most of it is ACH, so `payment_method` is a strong and partly simulator-specific signal (see the `channel` ablation).
- No device or IP data; location is known only for banks whose name states a country.
- Timestamps have minute resolution.
- Laundering *patterns* are multi-transaction graph structures; per-transaction features can only partly capture them. This is the case for the graph detector.
